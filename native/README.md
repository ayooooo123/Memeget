# Memeget Native

Standalone Android implementation using Kotlin, Compose, SQLite and a JNI inference adapter. Application ID: `com.memeget.nativeapp`; launcher label: **Memeget Native**. It installs alongside the React Native app and does not replace its package, database or private files.

**Verification is still in progress. Do not treat this directory as a completed parity release.** Current evidence and remaining checks are listed below.

## Build

Build from this directory, within the repository checkout. The build reads an explicit allowlist of existing Kotlin media utilities and fonts from `../modules/memeget-bg/android/src/main`; it copies them into generated build directories without modifying the original module. No React, Expo or JavaScript runtime is included in the APK.

Requirements:

- JDK 17. The included wrapper pins Gradle 8.14.3 and its distribution SHA-256.
- Android SDK platform 36, Android platform tools, NDK `27.1.12297006`, CMake `3.22.1`.
- `ANDROID_HOME` pointing to the SDK, or an untracked `local.properties`.
- Network access for Maven dependencies and the checksum-pinned runtime archive.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Only ARM64 is packaged; minimum Android version is API 26. `runtime/bootstrap.sh` extracts the pinned `react-native-executorch@0.9.2` C++ dependencies into an ignored build cache after SHA-512 verification. This reuses the native runtime, not its React Native application layer. Model files are downloaded separately on demand and must match the sizes and SHA-256 digests in `app/src/main/java/com/memeget/nativeapp/inference/ModelRegistry.kt` before activation.

## Local use and migration

- Link a folder with Android's document picker, or import/share media, supported links, ZIP collections or teaching files. Temporary shared content is copied into private storage before its temporary permission expires.
- Browse immediately while analysis is pending. Waiting tiles show **Queued**; only the coordinator's active meme animates **Analyzing**. Failed indexing has a persisted **Analysis failed** status, cleared by retry or successful analysis; tapping **Index** retries failed items along with pending ones, while background work does not. Search combines indexed text, fuzzy terms and compatible semantic vectors; pagination uses stable keyset cursors. Text matches show first and the semantic pass then reorders them; until the first results arrive the Library says **Searching…** rather than reporting no matches. Typo corrections and prefix completions draw on the full-text index's own word list (an `fts4aux` view), and a semantic pass runs its text query once rather than once per meme.
- X's animated-GIF MP4s set the `ctts` box flags to 1, which Android's MP4 extractor rejects as malformed, so the platform can read neither frames nor a poster from them. Indexing zeroes those flags in its private working copy before reading frames and making the poster; originals are never modified and the content hash covers the original bytes.
- Every image and video frame reaches the image model and OCR as a 768-px-wide JPEG at quality 90, the way the original app prepared them, so natively computed vectors match its exports and teachings. This also covers WebP, GIF and HEIF, which the native decoder (OpenCV) cannot read; WebP is almost half of the images in one real library.
- Review tags, add positive/negative teachings, find similar images, and edit images or videos in Remix Studio. Image and video outputs are new files, never in-place changes to originals.
- The **Label** tab asks about the memes whose answers spread furthest: unlabeled memes with the most unlabeled look-alikes come first, and memes that already get a label on their own are skipped; a "not this" alone does not take a meme out. Each card offers up to three of your existing labels with **Yes** / **Not this**, plus a typed name with autocomplete. Answers are teachings and finish saving even if you leave the tab mid-save. Leaving the tab re-tags the library so they spread, at once or as soon as running indexing ends. The look-alike counting behind the queue runs in native code (`cpp/VectorKernels.cpp`): on a Pixel 5a running the debug app the first card shows about 3 s after the first open and about 1 s after later opens (0.96–0.99 s over three screen recordings), where the Kotlin loops took 16–18 s.
- Viewer **Copy meme** publishes an image/video content URI to Android's clipboard. **Remix Studio → Export → Copy to Clipboard** copies the rendered result without adding a library item or discarding the editing project. Viewer WebM copies are converted to H.264/AAC MP4; other supported media are copied without re-encoding. The destination app must support pasting that media type.
- Debug builds keep the screen awake only while the app's window is visible. Release builds and device lock security are unchanged; this does not bypass the lock screen or keep other apps awake.
- The editor includes text, drawing, crop/rotation/flip/aspect, OCR replacement, cover/pixelation, subjects, stickers, backgrounds, ordering and undo/redo. Video composition supports retained ranges, speed/audio/music, title cards and time-aware overlays. Animated GIF export and automatic video subject isolation remain unsupported; manual motion/keyframes are supported.
- Keep the original app installed during migration. First make its latest folder backup, then link that folder in the native app. Legacy filename-based imports are marked as legacy evidence, not certified matches to current file bytes. Imported text remains searchable while compatible local records are rebuilt.
- For a device move, use the original app's **Settings → Folder backup → Back up now**, then copy every linked folder including hidden `.memeget`, preserving names and layout. Compare backup coverage with the collection before assuming private/unlinked imports were included. **Export collection (zip)** version 1 contains resized JPEGs and video posters; version 2 preserves original image/video bytes and stored classification metadata, including tag scores. Re-export with the updated original app when full media is required. Native ZIP intake imports the media and, from `manifest.json`, what a person or the bytes vouch for: hand tags and teach-sheet labels (as confirmed hand tags), OCR and transcripts, matched to each file by archive path, including files already in the library. Machine predictions and captions are not restored. Version 2 exports also supply each item's image vector, so those items index without running the image or text models; version 1 previews do not, because their vectors describe the original files rather than the resized copies. An exported vector and OCR are reused only while the file still has the exported bytes (same SHA-256); a changed file is analyzed fresh. When the manifest cannot be read (over 2 GiB, or damaged) the media still import and the import reports that their labels did not. Preserve an immutable prediction/metadata snapshot before reindexing for an accuracy comparison.
- Native folder backups are explicit and write only `.memeget-native`. Generation-addressed chunks are written before the manifest so interruption does not replace the previous complete generation. The legacy `.memeget` namespace is read-only.
- Sidecars do not transfer Android permissions, model downloads, private editor drafts, settings or credentials. Teaching files retain their declared model fingerprint; a vector from another recipe is not silently marked current. Native teaching files reject unknown schema versions and missing fingerprints. Teaching files can be shared to the app or picked in Settings. Each example attaches to the meme it shows (image vectors at cosine ≥ 0.985) when the teaching file is imported, when a collection is imported after it, and when indexing first gives that meme a vector: a "this is X" example becomes a confirmed tag there, and a "not X" example a rejection that also removes X from the meme's search text, cloud caption and terms included. A user's own tag on that meme is never overridden.
- The original `mobileclip-s2` teaching fingerprint is accepted after independent comparison of 32 images and eight texts against the original encoder recipe. It remains unchanged on import/export. Other foreign fingerprints are excluded from training. Encoder compatibility does not verify media identity: filename-only restores discard stored vectors and reviewed identities, preserve imported text, and require fresh indexing.
- Removing an indexed item does not delete the user's original media. Shared/imported copies owned by this app can be removed with their entries.

## Identification

People's labels spread to look-alike memes through a nearest-neighbour vote over image vectors (`LookalikeVote`). The references are taught examples and memes carrying a confirmed label; "not X" teachings and per-meme rejections are counter-examples. A meme gets a label when the winning label among its five nearest references has a reference at cosine ≥ 0.80 and no "not X" example of it is closer. Exact copies of a labeled picture always carry its labels.

A label applies on its own only after it held up on people's own labeled memes: each labeled meme is voted on with its own labels and copies left out, and a label needs at least three such votes, 90% of them right. Other labels stay suggestions for the Label tab until answers prove them. The vote has no training step; its index rebuilds only when people's labels, teachings or the vectors behind them change.

Measured on one real 2,370-meme library with the owner's 602 labeled memes split in half, each half's settings chosen on the other half: the vote agreed with his labels 89% of the time and labeled 27% of held-out memes, returning none of the labels he had rejected on them. Per-label logistic heads (the previous learner) labeled 28% at 57% agreement and returned 10 rejected labels; best-example retrieval labeled 79% at 20% agreement because it gives every meme five labels, so it now only ranks suggestions. Agreement here is with that owner's incomplete labels on memes he chose to label, not verified accuracy on the rest of a library.

Re-classification replaces the machine tags it recomputes (zero-shot prompts, learned look-alike labels, OCR rules) instead of merging old ones back, keeps human-confirmed tags whatever the caller passes, and rebuilds association terms from the final tag list. A "not X" teaching therefore also removes X, and its search terms, from near-copies (cosine ≥ 0.85) on the next re-tag. Per-meme rejections veto machine tags only: tagging X by hand withdraws an earlier "not X" on that meme, and re-tagging never drops a hand tag.

## Optional cloud assistance

Cloud assistance, automatic escalation and media/transcript consent are **off by default**. Configure them in Settings only if wanted. There are separate adapters for hosted Typesafe System One/JEV, Cloudflare Clef/Clef-flash, and an HTTPS self-hosted System One-compatible service. JEV is a decision model here, not JEPA and not a resident phone model. Optional captions use a separately configured OpenAI-compatible HTTPS endpoint.

Text-state consent can disclose OCR or caption content; it is not anonymous. Visual consent allows at most two stripped, resized frames. Transcript consent is separate. Filenames, local paths and embeddings are not ordinary request fields. Enabling automatic escalation applies to new uncertain items; including the existing backlog requires a separate opt-in.

Provider probabilities describe a provider's choice distribution, **not measured identification accuracy**. Cloud suggestions retain source, score domain, review status and provenance. They do not become manual labels or training examples merely because the provider was confident. Explicit acceptance creates a human-reviewed teaching while keeping its cloud origin. Rejection persists a veto and removes the corresponding weak prototype.

Saved cloud observations can improve offline retrieval without retraining a large model: a bounded local vector memory supplies explicitly unreviewed `cloud_hint` candidates for similar content. Captions are not copied onto similar images with different text. Disabling cloud stops future requests but keeps saved evidence for offline use. **Forget cloud** removes unreviewed observations and weak memory while retaining human-confirmed teachings and rejections.

Credentials are encrypted using Android Keystore. Cloud configuration, consent, credentials, request bookkeeping and caches are excluded from OS backup/transfer. No ambient development-agent credentials are used.

## Resource and network limits

- One inference family at a time; primary image/text encoders share a family. Heavy optional captions, speech and DINO enrichment are disabled by default.
- Core MobileCLIP-S2 plus English CRAFT/CRNN OCR artifacts need about 420 MiB. DINO, Whisper tiny.en and FastSAM bring the encoder and helper models to about 1.0 GiB.
- Local AI captions use MiniCPM-V 4.7 1B on the CPU through llama.cpp b11588, pinned in `runtime/bootstrap.sh`. The first caption downloads a 641 MiB Q4_K_M language model and a 1.03 GiB vision projector, both pinned by size and SHA-256. The projector ships as BF16, which ARMv8.2 CPUs such as the Pixel 5a's only run through a slow fallback, so the app converts it once to F16 (99.97% of values unchanged; none above 1e-3 change), checks the result against its own pinned SHA-256 and deletes the BF16 file. Disk use is about 1.7 GiB after that, 2.7 GiB during the conversion.
- Captions scale each image or video frame to at most 448×448 pixels, so a frame needs one vision encoder pass; videos use up to three frames. In the app on the Pixel 5a (cooled down, on battery), each frame took 15–24 s with 2 threads: vision 7.6–11 s, prompt 4.4–7 s, reply 3–7.6 s. A command-line build of the same runner took about 4 s to load and 15–17 s per image. Memory was about 2.1 GB (PSS) while captioning and about 280 MB after the session. One seven-minute session captioned seven memes, most of them three-frame videos. Each caption is saved as soon as it is made, so a session limit or Stop only repeats the meme in progress. The app uses the faster cores only: 2 threads on the 5a, at most 4 elsewhere. With the original BF16 projector the vision step alone took 66–101 s.
- Captions never hold up indexing. Indexing batches skip the caption step; captions are written afterwards for already-indexed memes, a batch at a time, until the session ends. A session started with **Index** captions only once its indexing queue is empty; a background run indexes up to 32 memes and then spends its remaining time on captions. On the Pixel 5a that is about 20 s per image and about a minute per video, so a library of a few thousand memes needs many sessions; background work while charging finishes it without tapping **Index**.
- Indexing uses batches of 32 and seven-minute coroutine sessions, preserving pending work on cancellation. A single native kernel cannot be interrupted midway; this is not a hard process-kill deadline. Heavy enrichment pauses for severe thermal state or low battery.
- Thumbnail disk cache: 128 MiB. Search uses bounded vector batches/cache and bounded result selection rather than an all-library sort in memory.
- Weak cloud memory: at most 2,048 vectors of 512 floats, eight per label, 30-day expiry, and an 8 MiB serialized ceiling. Rejections are retained conservatively; saturation disables weak-memory growth rather than resurrecting discarded claims.
- One cloud request in flight. Complete serialized requests are limited to 1 MiB; responses to 64 KiB. Defaults: 20 requests, 10 MiB and an estimated $0.05 per day, normally on unmetered networks.
- Consent is rechecked before sending and before persistence. Revocation cancels in-flight work and rejects late results. Cancellation cannot recall bytes already sent. No automatic retries, redirects or implicit provider fallback. Uncertain delivery consumes its conservative reservation.
- The local cost ledger is an estimate. Configure a provider-account spending cap for a hard monetary limit.
